# PPR Quality Analysis Copilot 迭代约束

收到本包后，先阅读本文件和 README.md，再阅读用户指定的基线 HTML。
本文件是项目默认约束；用户本轮明确要求的改变优先于默认约束。

## 按需修改

- 只实现用户本轮具体描述的需求，以及实现它必不可少的关联修改。
- 未要求修改的界面、文案、颜色、字体、间距、交互、布局、导航、功能、数据、计算逻辑、依赖和存储方式保持原样。
- 不主动整体美化、重设计、重构、升级依赖、增删菜单或扩展功能。
- 在已有源码上增量修改，不重新生成整个产品。
- 清楚的局部需求直接执行；需要扩大范围或存在影响业务结果的关键歧义时，先说明再请用户确认。
- 无关问题仅报告，不顺带修改。

## Git 版本与回退

- Git 提交历史是项目版本记录的唯一默认来源。直接在现有项目文件上增量修改；原型入口继续使用根目录 `index.html`，不要为每轮改动另存 `index_V1.1.html` 等副本。
- `history/index_V1.0.html` 是原始基线备份，禁止覆盖或删除。其他版本通过 Git 提交、分支或标签识别，不额外复制完整 HTML 或维护手工版本表。
- 开始前检查当前分支、`git status` 和相关提交历史。保留工作区中已有的用户修改；基线优先采用用户明确指定的提交、标签、分支或文件。若基线存在关键歧义，先确认，不自行推断哪个版本已获认可。
- 用户要求回退时，先定位目标提交或基线，再通过新的修改/回退提交恢复所需内容。共享或已推送的历史不得擅自改写；不使用强制推送、硬重置或删除历史来实现回退。
- 用户要求撤销上一轮或其中一项时，只撤销对应改动；若会影响其他已认可功能，先说明关联影响。
- 提交、推送、创建标签或发布版本按用户本轮要求执行；未明确要求时不擅自提交或推送。
- 除非用户明确要求交付归档包，不创建新的完整 ZIP 或版本 HTML 副本。
- Git 回退 HTML 代码不等于回退浏览器 `localStorage` 数据。不得自动清空或重置工程师记录；如确需变更存储结构，先提供兼容与数据备份方案。

## 当前技术与业务边界

- 单文件原生 HTML/CSS/JavaScript，ECharts 通过 CDN 加载。无后端、数据库或构建步骤。
- 不接入真实 AI、QMS、MES、OA、邮件服务或新增后端，除非用户明确要求。
- 保留 R1～R5 顺序判断、人机协同、缺失不圆度显示“无数据”、工程师验证与 8D 数据继承等现有规则，除非本轮明确修改。
- Mock Data、演示配置、独立模拟 Golden Batch 和 AI 预设结果的性质不能被改写为正式生产能力。
- 保持 localStorage 键和既有记录兼容；禁止以重置数据掩盖问题。
- 原文件现状是实现基线，并非所有需求均已验收的证明；不要把未验证能力写成已经验证。

## 交付与验证

- 在当前 Git 工作区直接修改项目文件。完成后检查差异，验证需求本身和必要的关联路径，并检查是否意外修改无关区域。
- 简短说明修改内容、所用基线、验证结果和未验证内容；如未提交或推送，明确说明当前 Git 状态。
- 双击 file://、HTTP 预览、实际离线运行的验证结果分别如实说明。原始版的自动化 file:// 测试曾受工具限制，不能宣称已通过。
- 交付应包含可直接运行的项目文件，不只提供截图、设计说明或需要用户自行拼接的代码片段。
