## 1. 这批数据能演示什么

| 文件 | 场景 | 预期告警 |
|---|---|---|
| `测试数据-12121D0050-全正常基线.xlsx` | 全部落在区间中段 | 18 条正常，异常页签为空 |
| `测试数据-12121D0051-壁厚连续3点接近下限.xlsx` | 壁厚第 2–4 点落进下限接近带 | **1 条中风险**（R5，挂第 4 点壁厚） |
| `测试数据-12121D0052-外径连续4点接近上限+不圆度2点接近.xlsx` | 外径连续 4 点贴上限；不圆度只有 2 点接近 | **1 条中风险**（R5，挂第 4 点外径）+ 1 个「2 点不升级」的边界反例 |
| `测试数据-12121D0053-三指标越限含一条记录双越限.xlsx` | 外径越高限、壁厚越低限、不圆度越高限 | **4 条高风险**（R3），其中一条记录同时贡献 2 条 |

四个批次合计：**高风险 4 条 + 中风险 2 条 + 正常 66 条 = 72 条事件**。

设备采集数据（每批 2 个文件：挤出机 温度/压力、牵引机 牵引速度，各 12 个采集点，每小时 1 条）不参与告警判定，用途是让**诊断页的设备工艺趋势图有数据可看**，并在诊断结论的「设备时序待对齐」里带上可读的采集值。

> 为什么设备采集不告警：`ppr_equipment_reading` 只有采集值列，规格表里也没有对应的工艺限值，判定引擎（`alert-engine.ts`）只判外径/壁厚/不圆度三个产品指标。这是设计如此，不是缺数据。

## 2. 导入前提（很重要）

数据全部挂在演示规格 **`SPEC-25X4.2` / PPR S2.5 25×4.2 瓷芯管** 下，限值必须是：

| 指标 | 标准区间 | 接近带（区间宽度 × 15%） |
|---|---|---|
| 外径 | 25.000 – 25.500 mm | 25.000–25.075 / 25.425–25.500 |
| 壁厚 | 4.200 – 4.800 mm | 4.200–4.290 / 4.710–4.800 |
| 不圆度 | 0 – 0.350 mm | 0–0.0525 / 0.2975–0.350 |

**服务器上的规格限值如果和上表不一致，告警结果一定对不上。** 演示前请先在
「管理中心 → 数据源管理 → 产品台账」里核对这条规格的五个限值字段。

批次号 `12121D0050 ~ 12121D0053` 与产品规格直接写在每条检验记录上（批次不落表），导入产品数据后批次随即出现在
「批次总览」里，不需要也不能先手工建批次；如果服务器上已被占用，改掉文件里 `batch_no` 一列即可（同一批内保持一致，
且同一个批次号只能对应一个规格）。

## 3. 导入步骤

### 3.1 产品数据（触发告警）

**在「产品台账 → 规格页」或「批次总览」页导入即可，批次不需要（也不能）先手工建批次。**

1. 打开导入页：
   - **产品台账** → 点规格「PPR S2.5 25×4.2 瓷芯管」→ 进入该规格的生产批次页。
     在这里导入，规格由页面固定（页面上下文优先于文件里的 `spec_code`）。
   - **批次总览**（数据源管理 → 批次总览）→ 同样提供产品数据导入入口；
     规格按「文件里的 `spec_code` / `spec_name` → 该批次已有检验记录上的规格」解析。
2. 点「Excel 导入」，选 `测试数据-12121D0051-壁厚连续3点接近下限.xlsx`。
   文件自带 `batch_no` / `spec_code` / `production_group` / `batch_start_time`，批次号与规格直接落在每条检验记录上。
3. 导入完成的提示应显示：`导入完成：成功 6 / 6 条检验记录`，补充说明里带
   `批次 12121D0051 ｜ 自动预警：高风险 0 条，中风险 1 条`。

> **系统按表头判断文件类型**：带 `record_no` + `inspect_time` 的产品数据文件走检验记录接口，
> 把 `batch_no` 与规格写到检验记录行上，批次随即出现在「批次总览」；设备采集文件（只有采集时间 + 采集项）
> 走采集数据接口，批次号由导入时在页面上选定（见 3.2）。
> 批次不能手工新建或编辑（接口对批次的 POST/PUT 直接报错），明细数据也只能 Excel 导入，
> 导入幂等——同一个 `record_no` 重复导入会覆盖原有数值，导错重导一次即可。
> 从设备台账进入的批次页只提供「导入采集数据」，不再在这里导入产品数据。

**演示当天建议的讲解顺序**：0050（先看「没有告警」的正常态）→ 0051（中风险 R5）→
0052（边界反例 + 长连续段只算 1 条）→ 0053（高风险 R3，含双指标同越）。

### 3.2 设备采集数据（补趋势图）

产品数据导入后批次号已经存在，再到设备台账按批次号挂采集数据 —— **导入时先选批次号，再上传文件**：

1. 设备台账 → 选「1号挤出机」→ 点右上角「导入采集数据」。
2. 在弹窗里**先选批次号** `12121D0051`（候选来自已有批次，也就是产品数据导入出来的批次号），
   再选文件 `12121D0051-挤出机-温度压力.xlsx`（12 条，每小时 1 条）。
   导完这一轮，该批次就出现在这台设备的批次列表里，点「采集数据」可以查看。
3. 回到设备台账 → 选「1号牵引机」→ 同样点「导入采集数据」，选同一个批次号 `12121D0051` →
   导入 `12121D0051-牵引机-牵引速度.xlsx`。

> **批次在设备下的可见性由采集数据反推**：批次不再保存「归属哪台设备」，
> 设备台账里只列出「已经在本设备下导过采集数据」的批次。在产品台账规格页导入的批次，
> 只要在设备台账里按批次号导一次采集数据就会出现在该设备下，不需要（也不能）编辑批次来补设备归属。

每个批次都要分别在**挤出机**和**牵引机**下各导一次（页面的采集项列由设备类型决定，
文件列头已经按类型对好：挤出机是 `collect_time + temperature_c + pressure_mpa`，
牵引机是 `collect_time + haul_off_speed_mpm`）。

> 采集数据的唯一键是 `(equipment_id, batch_no, collect_time)`：同一文件重复导入会**覆盖原有数值**（幂等），
> 不会报错也不会产生重复行，导错重导一次即可。

### 3.3 每批设备采集曲线设计

采集值本身不影响告警，但和产品异常时刻做了对应，诊断时更有说服力：

| 批次 | 曲线特征（对应第 4~7 个采集点） |
|---|---|
| 0050 | 平稳波动（温度 ±0.06℃、压力 ±0.015MPa） |
| 0051 | 温度下降约 0.7℃、压力上升约 0.2MPa、牵引速度上升约 0.06 — 对应壁厚偏薄 |
| 0052 | 温度上升约 0.4℃、压力下降约 0.12MPa、牵引速度上升约 0.03 — 对应外径偏大 |
| 0053 | 温度小幅上升约 0.3℃、压力先降后升、牵引速度有跳动 — 对应三指标越限 |

## 5. 重新生成 / 复算校验

```bash
cd PPR/code

# 重新生成全部 Excel（不连数据库，生成时会自检告警条数）
node scripts/demo-data/generate-alert-demo.js

# 走真实导入路径写本地 MySQL，再用真实判定引擎复算比对（默认校验完清理数据）
npx tsx scripts/demo-data/verify-alert-demo.mts

# 想保留数据在页面点检（批次号为 12121D0050 ~ 12121D0053）
npx tsx scripts/demo-data/verify-alert-demo.mts --keep

# 一键导入并核对：按新数据模型走真实接口（产品数据 → 按批次号导入采集数据 → 对照 演示结果对照表.json）
node scripts/demo-data/import-demo-data.mjs
# 默认连 http://127.0.0.1:9010，可用 --base 指定其他地址
```

校验脚本会断言 271 项，覆盖：文件行数与表头、批次号随检验记录落库（批次不落表，无需先建批次）、
`decimal(10,3)` 落库精度、设备采集文件列头与点数、`evaluateAlerts()` 的三级事件条数、`quality_flag` 回写、
事件编号后缀与状态（`normal → closed`、中/高风险 → `open`）。`import-demo-data.mjs` 则按
「产品数据 → 设备采集数据（先选批次号）」的顺序导入，并逐批核对事件数与质量标记数。

> 校验脚本运行时会**临时**把 `system_config.wecom_alert_enabled` 改成 `false`
> 并在结束时恢复原值 —— 本地这个开关是打开的且配了真实 Webhook，不关掉会真的往群里推。
> 你自己在服务器上导入时不会经过这个脚本，该开关保持你想演示的状态即可。

## 6. 注意事项

1. **企微推送会被真实触发**。服务器上如果开着「推送中/高风险预警」，导入 0051/0052/0053
   会在合并窗口（默认 5 秒）后推一条汇总消息。演示前确认群里是否适合收到。
   同一批数据重复导入会**按 `record_no` 覆盖**已有检验记录（导入幂等），事件级别没变时
   不会重复推送；只有新增或升级的事件才会再次推送。
2. **事件编号含记录自增 ID**，所以服务器上生成的编号与本地校验时的编号不同，
   形如 `QE-20261117-105WT`（日期-记录ID-指标后缀）。对照结果时请以
   **批次号 + 指标 + 规则码** 为准，不要死记编号。
3. **一次导入一个文件**，不要把四个批次的数据合成一个文件：批次号不同，合成后虽然也能导入，
   但不利于按场景分步演示。
4. **0050 是必要的**。只有先演示「正常批次没有告警」，才能说明 R0/R3/R5 不是把所有数据都报出来。
5. 若要演示**规格改动触发全批次重算**，可以在导入后修改一次该规格的 `wall_lower_mm`
   （例如从 4.200 改成 4.180），0053 的壁厚 4.170 就会从高风险降为中风险/正常，改回即恢复。
6. **采集数据只按批次号挂靠**，批次不能手工新建或编辑；如果要重来，可以在「批次总览」里
   删除该批次（会连同检验记录、采集数据与预警事件一起清理，已归档 8D 报告的批次会被拒绝）。
